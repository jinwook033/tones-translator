# 톤즈의원 번역기 (tones-translator)

용어집 기반 의료 원고 번역기. `blog-rank-multi` 에서 번역 기능만 떼어낸 **독립 앱**입니다.

## 실행

```bash
npm install
cp .env.example .env.local     # 키 입력
npm run dev                    # http://localhost:3300
```

로그인이 없습니다. 원본은 멀티 테넌트 + 로그인이었지만 이 앱은 톤즈 전용 도구입니다.

## 화면

| 주소 | 내용 |
|---|---|
| `/` | 대시보드 — 검수 대기 현황과 손봐야 할 것 |
| `/translate` | 번역 — 한국어 원고 → 4개 언어 |
| `/excel` | 엑셀 일괄 — 파일 단위 번역과 다운로드 |
| `/review` | 검수 — 결과를 보고 항목별로 고치는 곳 |
| `/glossary` | 용어집 — 용어 고정과 분류 |
| `/language` | 언어 설정 — 검수자가 규칙을 미리 정해두는 곳 |

화면은 1280px 이상 데스크톱 기준입니다. 디자인은 `design/` 에 있습니다.

## 언어 설정

언어마다 **금지 표현 · 대조 예문 · 문체 규칙**을 따로 둡니다. 일본어는 일본인이, 중국어는 중국인이
`/translator/language` 에서 직접 고치고, 저장하면 **다음 번역부터 바로** 프롬프트에 반영됩니다.

```
LANGUAGE_PROFILE_SEED          코드 기본값 (lib/translator/language-profile.ts)
data/language-profiles.json    화면에서 고친 내용 (서버를 껐다 켜도 유지)
```

용어집과 같은 두 겹 구조이고, 같은 언어가 양쪽에 있으면 **파일 쪽이 이깁니다.**
언어별로 「기본값으로」 버튼을 눌러 코드 기본값으로 되돌릴 수 있습니다.

## 검수

번역 결과는 `/translator/review` 에 **검수 대기**로 쌓입니다. 검수자가 항목별로 고치거나 승인하면
**같은 원문이 다시 왔을 때 그 번역을 그대로 씁니다** — 다시 번역하지 않고 비용도 들지 않습니다.
검증기가 잡은 항목이 맨 위로 올라오므로 위험한 것부터 보면 됩니다.

고친 내용을 앞으로 계속 적용하려면 두 가지 방법이 있고, 강도가 다릅니다.

| 방법 | 강도 | 쓸 때 |
|---|---|---|
| 「이 수정을 예문으로」 버튼 | 부드러움 — 문체 전반을 유도 | 어투·표현 방향을 바꾸고 싶을 때 |
| 언어 설정에 금지 표현 추가 | 강함 — 그 표현을 확실히 차단 | 특정 단어가 반드시 나오면 안 될 때 |

실측 예: `担当`(사무적 담당)을 안 쓰게 하려고 예문만 올렸을 때는 `直接ご担当いたします` 로 남았고,
금지 표현을 함께 넣자 `自ら行う` 로 바뀌었습니다. **둘을 같이 쓰는 게 확실합니다.**

저장 위치는 `data/review.json` 입니다.

## 언어

`en` 영어 · `cn` 중국어(간체) · `tw` 대만어(번체) · `ja` 일본어 · `ko` 한국어

`tw` 는 예전에 `sg`(싱가포르)라는 이름이었지만 내용은 처음부터 대만 기준이었습니다 — 2026-09-16 에 이름을 바로잡았습니다.

## 용어집

두 겹입니다.

```
GLOSSARY_SEED        코드로 관리하는 검증 용어 226건 (lib/translator/glossary-data.ts)
data/glossary.json   화면에서 추가·수정한 용어 (서버 재시작해도 유지)
```

같은 단어가 양쪽에 있으면 **파일 쪽이 이깁니다** (사람이 고친 것이므로).

용어는 13개 분류로 나뉘고, 분류가 **토큰으로 가릴지 말지**를 정합니다.
고유명사(`brand` `person` `location` `device` `equipment` `product` `procedure` `category` `menu`)는 가려서 번역값을 고정하고,
일반어(`anatomy` `condition` `general` `tag`)는 가리지 않고 모델이 문맥으로 옮깁니다 — 가리면 어순이 깨지기 때문입니다.

추가·수정 방법과 분류 기준은 **[GLOSSARY.md](GLOSSARY.md)** 를 보세요.

## 원본과 달라진 점

| | blog-rank-multi | 이 앱 |
|---|---|---|
| 로그인 | 있음 | 없음 |
| 테넌트 | 여러 병원 | 톤즈 하나 (`lib/tenant.ts` 가 항상 1) |
| 용어집 저장 | Supabase | `data/glossary.json` |

번역 로직(`lib/translator/`)은 **원본 그대로**입니다. 용어집 SEED 226건도 동일합니다.
